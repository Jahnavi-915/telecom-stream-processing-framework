# Pthreads + Socket Integration Design

## Overview

This document describes the design of the integrated POSIX Threads and TCP Socket Programming architecture developed as part of the Telecom Stream Processing Framework project.

The objective of this integration is to combine the shared-memory Producer–Consumer processing model with network-based communication to create an end-to-end telecom packet streaming prototype.

The integrated system simulates how telecom packets are generated, buffered, transmitted across a communication channel, and received by a client application.

---

## Objective

The primary objective of this integration is to establish a complete packet streaming workflow that combines packet generation, buffering, synchronization, transmission, and reception within a single architecture.

The integrated prototype serves as the first step toward future telecom stream-processing systems involving Multiple Data Extraction Servers (DES), MPI-based communication, and Hybrid MPI + POSIX Threads architectures.

---

## Integrated Architecture

### High-Level Workflow

```text
Producer Thread
       ↓
Shared Buffer
       ↓
Sender Thread
       ↓
TCP Socket
       ↓
Client
       ↓
Packet Logging
```

---

## Component Description

### Producer Thread

The Producer Thread acts as a telecom packet generator.

Responsibilities:

* Generate telecom packets.
* Assign packet identifiers.
* Populate packet fields.
* Insert packets into the shared buffer.
* Signal the Sender Thread when packets become available.

The Producer Thread functions similarly to a Data Extraction Server (DES) generating telecom traffic.

---

### Shared Buffer

The Shared Buffer acts as an intermediate storage area between packet generation and packet transmission.

Responsibilities:

* Store generated packets temporarily.
* Synchronize Producer and Sender Thread execution.
* Prevent packet loss due to timing differences.
* Maintain packet ordering.

The shared buffer is implemented using a circular queue.

---

### Sender Thread

The Sender Thread replaces the Consumer Thread used in the Week 1 Producer–Consumer implementation.

Responsibilities:

* Remove packets from the shared buffer.
* Establish communication with the socket layer.
* Transmit packets to the connected client.
* Collect transmission statistics.

The Sender Thread acts as a bridge between local packet processing and network communication.

---

### TCP Socket Layer

The TCP communication layer provides reliable packet transmission between the server and client.

Responsibilities:

* Maintain network communication.
* Provide reliable and ordered delivery.
* Transfer packets generated by the Sender Thread.
* Support future distributed processing architectures.

---

### Client

The Client receives telecom packets transmitted by the server.

Responsibilities:

* Establish connection with server.
* Receive incoming packets.
* Log received packets.
* Collect reception statistics.
* Validate packet delivery.

The Client represents a simplified telecom packet receiver.

## Packet Structure

The integrated prototype uses a telecom-oriented packet structure.

```c
typedef struct
{
    int packet_id;
    int priority;
    char source[50];
    char destination[50];
    char payload[100];
} Packet;
```

### Field Description

#### packet_id

Unique identifier assigned to each packet.

#### priority

Represents packet priority for future scheduling and traffic management experiments.

#### source

Source identifier representing the origin of the packet.

#### destination

Destination identifier representing the target receiver.

#### payload

Contains the packet data being transmitted.

## Packet Lifecycle

The lifecycle of a packet in the integrated architecture is:

```text
Packet Created
       ↓
Inserted into Shared Buffer
       ↓
Stored in Circular Queue
       ↓
Removed by Sender Thread
       ↓
Transmitted Through TCP Socket
       ↓
Received by Client
       ↓
Logged and Processed
```

---

## Synchronization Design

The Producer Thread and Sender Thread communicate through a shared circular buffer.

### Synchronization Mechanisms

The implementation utilizes:

* pthread_mutex_t
* pthread_cond_t not_full
* pthread_cond_t not_empty

These mechanisms ensure:

* Safe shared-buffer access.
* Race-condition prevention.
* Proper coordination between Producer and Sender Thread execution.
* Reliable packet transfer.
