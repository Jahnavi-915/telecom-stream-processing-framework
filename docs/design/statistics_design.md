# Statistics Design

## Objective

Collect performance, synchronization, utilization, and scalability metrics from the POSIX Threads Producer-Consumer prototype.

The collected statistics are used to evaluate correctness, synchronization efficiency, buffer behavior, throughput characteristics, and overall system performance under different operating conditions.

---

## Metrics

### Frames Produced

Total number of frames generated by the producer thread during execution.

Purpose:

* Verify producer functionality.
* Validate expected workload generation.
* Support frame integrity verification.

---

### Frames Consumed

Total number of frames processed by the consumer thread during execution.

Purpose:

* Verify consumer functionality.
* Validate successful frame processing.
* Compare against Frames Produced to detect frame loss or duplication.

---

### Buffer Full Events

Number of times the producer was forced to wait because the shared buffer reached maximum capacity.

Purpose:

* Measure producer blocking frequency.
* Identify buffer congestion conditions.
* Evaluate the impact of producer-heavy workloads.

---

### Buffer Empty Events

Number of times the consumer was forced to wait because the shared buffer contained no available frames.

Purpose:

* Measure consumer waiting frequency.
* Identify consumer starvation conditions.
* Evaluate the impact of consumer-heavy workloads.

---

### Execution Time

Total wall-clock execution time of the application measured from thread creation until completion.

Formula:

```text
Execution Time = End Time − Start Time
```

Unit:

```text
Seconds
```

Purpose:

* Measure overall runtime.
* Support throughput calculations.
* Compare performance across different test scenarios.

---

### Throughput

Number of frames successfully processed per second.

Formula:

```text
Throughput = Frames Consumed / Execution Time
```

Unit:

```text
Frames per Second (frames/sec)
```

Purpose:

* Measure processing efficiency.
* Evaluate performance scaling.
* Compare different workload configurations.

---

### Average Buffer Occupancy

Average number of frames present in the shared buffer during execution.

Formula:

```text
Average Buffer Occupancy =
Total Buffer Occupancy Samples / Occupancy Sample Count
```

Purpose:

* Measure overall buffer usage.
* Analyze producer-consumer balance.
* Support utilization calculations.

---

### Buffer Utilization

Percentage of the available buffer capacity utilized on average during execution.

Formula:

```text
Buffer Utilization =
(Average Buffer Occupancy / Buffer Size) × 100
```

Unit:

```text
Percentage (%)
```

Purpose:

* Measure effectiveness of buffer usage.
* Compare different buffer configurations.
* Evaluate workload characteristics.

---

## Metric Usage

The collected statistics are used to evaluate:

### Functional Behavior

* Frames Produced
* Frames Consumed

Used to verify:

* Correct frame generation
* Correct frame consumption
* Absence of frame loss
* Absence of frame duplication

---

### Synchronization Behavior

* Buffer Full Events
* Buffer Empty Events

Used to evaluate:

* Producer waiting behavior
* Consumer waiting behavior
* Mutex and condition variable effectiveness
* Synchronization efficiency

---

### Performance Behavior

* Execution Time
* Throughput
* Average Buffer Occupancy
* Buffer Utilization

Used to evaluate:

* Processing efficiency
* Buffer usage characteristics
* Performance scaling
* Workload handling capability

---

### Scalability Behavior

Used to evaluate:

* Increased workload handling
* High-volume processing
* Producer burst workloads
* Consumer burst workloads
* Maximum throughput scenarios

---

## Metric Validation

The statistics framework has been validated using the following test scenarios:

### Functional and Validation Tests

* TC-01 Balanced Baseline
* TC-02 Small Buffer
* TC-03 Large Buffer
* TC-04 Fast Producer
* TC-05 Fast Consumer
* TC-06 High Volume

### Extended Performance Tests

* TC-07 Slow System
* TC-08 Fast System
* TC-09 Maximum Throughput
* TC-10 Producer Burst
* TC-11 Consumer Burst

The collected metrics successfully characterized synchronization behavior, buffer utilization, workload scalability, and throughput variation across all test scenarios.

## Future Extensions

The same statistics framework can be reused for:

* Socket Programming implementations

* Comparative evaluation of external team implementations
* Advanced telecom packet processing workloads

## Conclusion

The statistics framework provides a consistent mechanism for evaluating correctness, synchronization behavior, performance characteristics, buffer utilization, and scalability of Producer-Consumer implementations developed within the Telecom Stream Processing Framework project.
